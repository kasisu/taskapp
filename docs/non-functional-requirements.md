# 非機能要件

## 1. 位置付け

非機能要件は、機能そのものではなく、アプリが満たす品質・利用条件・実装上の制約を定める。機能の一覧は[機能要件](functional-requirements.md)を参照する。

## 2. 要件一覧

| ID | 分類 | 要件 | 学習上の狙い |
|---|---|---|---|
| NFR-01 | 利用環境 | PCの最新Chromeで利用できることを対象とする。 | 対象環境を明確にし、検証範囲を限定する。 |
| NFR-02 | 操作性 | 追加、編集、削除、移動の操作対象が、画面上で判別できること。 | ボタン名、入力欄、操作状態を明確にする。 |
| NFR-03 | 応答性 | 通常の学習用データ量で、操作後に画面の更新を待たせないこと。 | Reactの状態更新と再描画の関係を理解する。 |
| NFR-04 | 永続性 | 保存に成功したデータは、ブラウザを再読み込みしても最後の状態を復元できること。 | localStorageへの保存と復元を学ぶ。 |
| NFR-05 | 信頼性 | 保存データの読み込みに失敗しても、アプリが停止せず初期状態で利用開始できること。保存に失敗した場合は利用者へ通知すること。 | JSON解析時の例外処理と復旧方針を学ぶ。 |
| NFR-06 | 保守性 | 画面、状態操作、保存処理の責務を分け、変更箇所を追いやすくすること。 | コンポーネント分割と状態管理を学ぶ。 |
| NFR-07 | アクセシビリティ | ボタンには操作内容が分かる名前を付け、入力欄にはラベルを関連付け、カード移動にはキーボード代替操作を提供すること。 | 基本的な利用しやすさを確保する。 |
| NFR-08 | セキュリティ | 個人情報・機密情報を保存しない。認証、権限管理、通信は対象外とする。 | localStorageの用途と限界を理解する。 |
| NFR-09 | 互換性 | 保存データの形式を変更する場合は、既存データへの影響を確認すること。 | データ形式の変更管理を学ぶ。 |

## 3. 今回は求めない品質

- 複数端末間の同期、バックアップ、復元保証
- 複数ユーザーの同時編集や権限管理
- 高負荷・大量データに対する性能保証
- ネットワーク障害への対応
- WCAG準拠などの包括的なアクセシビリティ監査

これらはバックエンドや運用設計が必要になるため、MVPの範囲外とする。
