# 機能要件

## 1. 対象範囲

対象は単一利用者が使う単一ボードのタスク管理である。詳細な画面構成は[画面設計](screen-design.md)、保存する情報は[データ設計](data-design.md)を参照する。

## 2. 要件一覧

| ID | 機能 | 要件 |
|---|---|---|
| FR-01 | ボード表示 | アプリ起動時に、保存済みのボード、リスト、カードを表示する。保存済みデータがない場合はサンプルボードを表示する。 |
| FR-02 | リスト追加 | 利用者はリスト名を入力し、ボードの末尾にリストを追加できる。 |
| FR-03 | リスト編集 | 利用者は既存リストの名前を変更できる。 |
| FR-04 | リスト削除 | 利用者はリストを削除できる。カードを含む場合は確認を求める。 |
| FR-05 | カード追加 | 利用者はリスト内にカード名を入力し、そのリストの末尾にカードを追加できる。 |
| FR-06 | カード編集 | 利用者は既存カードのタイトルを変更できる。 |
| FR-07 | カード削除 | 利用者はカードを削除できる。削除前に確認を求める。 |
| FR-08 | カード並べ替え | 利用者は同じリスト内で、カードをドラッグ&ドロップして順番を変更できる。 |
| FR-09 | カード移動 | 利用者はカードを別のリストへドラッグ&ドロップして移動できる。 |
| FR-10 | 保存 | リスト・カードの追加、編集、削除、移動後の状態をlocalStorageに保存する。 |
| FR-11 | 復元 | 次回起動またはリロード時に、保存した状態を復元する。 |
| FR-12 | キーボード代替操作 | キーボードだけでも、カードを同一リスト内または別リストへ移動できる操作を提供する。 |

## 3. 入力・削除時のルール

- リスト名とカード名は、空文字および空白だけでは登録・更新できない。
- 入力値の前後にある空白は削除して保存する。
- 登録できない場合は、理由が利用者に分かるメッセージを表示する。
- 削除確認で取り消した場合は、データを変更しない。
- リスト削除を確定した場合、そのリストに属するカードも削除する。
- カードとリストの削除は、確認後に完全に削除する。アーカイブ、復元、取り消し機能はMVPに含めない。

## 4. カード移動のルール

- カードは、同じリスト内と別リスト間で移動できる。
- 移動先はカードの先頭、カード間、末尾、およびカードが0件のリストとする。
- ドラッグ操作を取り消した場合、または有効なドロップ先以外で終了した場合、データを変更しない。
- キーボード代替操作の具体的なUIは、ドラッグ&ドロップライブラリの選定時に決める。

## 5. 対象外

複数ボード、ラベル、期限、説明文、チェックリスト、コメント、担当者、検索、共同編集、ログイン、リスト自体の並べ替えは今回のMVPに含めない。
