# 技術スタック（内部設計資料）

この資料は、実装担当者向けの技術選定資料であり、顧客向けの要件定義書とは分けて扱う。

## 1. 決定状況

| 区分 | 技術・方針 | 状態 | 理由 |
|---|---|---|---|
| UI | React | 決定 | コンポーネント設計と状態更新を学ぶ対象にする。 |
| 開発環境 | Vite | 決定 | Reactの学習用プロジェクトを軽量に開始できる。 |
| 実装言語 | JavaScript または TypeScript | 未決定 | 初期化前に、学習優先度に合わせて選ぶ。 |
| ドラッグ&ドロップ | 専用ライブラリ（候補：`@dnd-kit`） | 未決定 | 実装前に、Reactとの相性、学習コスト、キーボード操作への対応を比較して選ぶ。 |
| 状態管理 | React標準の状態管理から開始 | 決定 | MVPの状態規模では、まずpropsとstateの流れを理解する。 |
| 保存先 | ブラウザのlocalStorage | 決定 | バックエンドなしで、永続化の基本を学ぶ。 |
| バックエンド | 使用しない | 決定 | 認証・共有・DB運用をMVPから外し、フロントエンド学習に集中する。 |
| スタイル | CSS | 決定 | UIの構造と見た目の責務を分離し、Trello風のボード・リスト・カードの階層を表現する。 |
| テスト | 手動確認を基本とし、必要に応じて自動テストを導入 | 段階導入 | まず要件どおりに動くことを確認し、後からテストの価値を学ぶ。 |

## 2. 未決定事項

### JavaScript と TypeScript

- JavaScript：Reactの基本、状態管理、ドラッグ&ドロップに集中しやすい。
- TypeScript：データ構造や関数の入出力を明確にでき、規模が大きくなった際の安全性を学べる。

今回は学習範囲を小さく保つならJavaScript、型による安全性も学びたいならTypeScriptを選ぶ。選定後は、この資料と要件定義書を更新する。

### ドラッグ&ドロップライブラリ

候補の`@dnd-kit`は、React向けで、並べ替えとリスト間移動を実現しやすい。一方で、ライブラリの概念を学ぶ時間が必要になる。選定時は、公式ドキュメント、キーボード操作への対応、メンテナンス状況を確認する。

## 3. localStorage採用時の制約

- 保存データは同じブラウザ・同じ端末でのみ利用できる。
- 端末変更やブラウザデータ削除による消失を防げない。
- 他の利用者との共有や同時編集はできない。
- 秘密情報を保存する用途には使わない。
